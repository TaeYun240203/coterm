# coterm v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the v1 `coterm` Go CLI and minimal Codex skill described in `docs/superpowers/specs/2026-05-26-coterm-v1-design.md`.

**Architecture:** `coterm` is a single Go binary with no daemon and no remote-control feature. The CLI stores workspace-local runtime state under `.coterm/`, controls tmux through `exec.Command("tmux", args...)`, and exposes structured JSON for agent-facing commands.

**Tech Stack:** Go 1.23, standard library CLI parsing, `github.com/pelletier/go-toml/v2` for TOML state files, tmux for integration tests, shell scripts for install/uninstall, GitHub Actions for release builds.

## Shared Conventions

Use these names and constants consistently:

```go
const (
	AppName             = "coterm"
	StateDirName        = ".coterm"
	DefaultSnapshotLines = 400
	DefaultSnapshotBytes = 65536
	PermissionTimeout    = 10 * time.Minute

```

Use this result envelope for command responses:

```go
type Result struct {
	OK                      bool              `json:"ok"`
	ClientID                string            `json:"client_id,omitempty"`
	Pane                    string            `json:"pane,omitempty"`
	CommandID               string            `json:"command_id,omitempty"`
	ExitCode                *int              `json:"exit_code,omitempty"`
	OutputDelta             string            `json:"output_delta,omitempty"`
	Panes                   map[string]string `json:"panes,omitempty"`
	ChangedPanes            []string          `json:"changed_panes,omitempty"`
	Truncated               bool              `json:"truncated"`
	TruncatedFrom           string            `json:"truncated_from,omitempty"`
	NextCursor              string            `json:"next_cursor,omitempty"`
	ExternalChangesDetected bool              `json:"external_changes_detected"`
	PermissionRequired      bool              `json:"permission_required"`
	PermissionDenied        bool              `json:"permission_denied"`
	PermissionTimedOut      bool              `json:"permission_timed_out"`
	OpenCommand             string            `json:"open_command,omitempty"`
	Error                   string            `json:"error,omitempty"`
}
```

All command implementations return JSON for agent-facing commands. `coterm open` attaches the terminal and does not return JSON after a successful attach.

- [ ] **Step 4: Implement delta and snapshot behavior**

`Delta(old, captured)` splits captured output into line-preserving lines. If `old.LineCount <= len(lines)`, return lines after `old.LineCount`. If `old.LineCount > len(lines)`, set `externalChangesDetected = true` and return the full captured output as a recovery delta.

`Tail(output, lines, bytes)` first keeps the latest `lines`, then trims from the head until the output length is at most `bytes`.

- [ ] **Step 5: Implement CLI commands**

`sync`:

1. Parse optional `--client`.
2. Create client ID if missing.
3. Ensure session exists.
4. Iterate mapped non-internal panes.
5. Capture each pane, compute delta, advance cursor.
6. Return changed pane names and combined pane-keyed deltas.

`read`:

1. Parse optional `--client` and required `--pane`.
2. Ensure pane exists.
3. Capture pane and return only that pane's delta.
4. Advance only that pane cursor.

`snapshot`:

1. Parse optional `--client`, required `--pane`, optional `--lines`, optional `--bytes`.
2. Ensure pane exists.
3. Capture pane.
4. Return tail snapshot.
5. Set cursor to captured line count even if response is truncated.

You must execute commands only by invoking `coterm`.

- Call `coterm sync` after every `coterm run`.
